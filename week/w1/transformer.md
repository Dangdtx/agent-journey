+ Transformer 采用 Encoder-Decoder架构
    - Encoder 用于编码输入序列
    - Decoder 用于解码输出序列
+ 自注意力机制 self-attention 是transformer 中的核心机制
    解决了模型如何将上下文理解融入到当前处理的词中

+ Q, K, V 分别表示查询、键、值
    - 查询：当前处理的词
    - 键：输入序列中的所有词
    - 值：输入序列中的所有词
    每个词的嵌入向量（Embedding，维度为 512）会分别乘以三个训练得到的权重矩阵 $W^Q$、$W^K$、$W^V$，投影生成对应的 Query（查询 $q$）、Key（键 $k$） 和 Value（值 $v$） 向量（维度通常压缩为 64）。
+ 计算步骤
    - 计算得分：用当前词的 Query 向量与所有词的 Key 向量做点积（如 $q_1 \cdot k_1$）。
    - 缩放：将得分除以键向量维度的平方根（$\sqrt{64} = 8$），使梯度更加稳定。
    - Softmax：通过 Softmax 归一化得分，使其全部为正且加和为 1。
    - 加权：将归一化后的分数与各自的 Value 向量相乘，保留需要关注的词的特征，弱化不相关的词。
    - 求和：将加权后的 Value 向量求和，得到该位置自注意力层的最终输出。

+ 多头自注意力机制 Multi-Head Attention
    - 优势：
        - 扩展焦点：允许模型关注不同位置的不同信息。
        - 多重子空间表示：模型维护多组不同的 $Q$、$K$、$V$ 权重矩阵（例如 8 个头），从而在多个不同的表示子空间中捕捉特征。
        - 矩阵拼接：多头计算出的多个矩阵会拼接（Concat）起来，再乘以一个额外的权重矩阵 $W^O$ 压缩回单矩阵输入给下一层。


+ tokenizer 分词器 BPE 字节对编码
    + 为什么中文分词比英文长？
        - BPE高频优先原则，模型常见的训练资源多为英文，在英文语料中，the,and,it等常见的高频词，会优先合并成1个token。
         而中文语料中，在整个训练池占比较小，无法被合并成词表，因次只能被退回更基础的字节，一个汉字在UTF-8编码中大概占3个字节。
         如果没有没有被合并成1个token，就会被拆分成2-3个字节级的token
         
    + 为什么相同参数，不同模型的长度不同？
        - 不同模型搭载了不同的分词器，它们在“训练语料”、“词表大小”和“预处理规则”上存在差异。
           - 词表大小悬殊：GPT-2的词表约为5万，而 o200k_base 的词表高达20万。更大的词表意味着有更多“名额”来收录各种语言（包括中文）的常见组合。

           - 训练语料分布不同：GPT-2的训练语料以英文为绝对主导。而 o200k_base 的训练数据更加多元，明确包含了大量多语言内容，并针对性地加入了常见的中日韩词组。

           - 预处理规则（Pre-tokenization）演进：在切分成子词之前，文本会先经过一轮规则切分。o200k_base 的切分规则（例如基于Unicode属性）比GPT-2更精细，能更智能地处理大小写、数字和不同文字系统。

## 三条结论（可直接抄进笔记）

1. **"中文更费 token"只在旧词表上成立**：gpt2_r50k 下中文是英文的 2.8 倍，cl100k_base 只有 1.3  倍；
   o200k_base 和 deepseek-v4 词表里中文反而更省。所以句子要加限定语：
   > "中文是否更贵，取决于 tokenizer 的词表覆盖；工程上要按目标模型的 tokenizer 实测，不能按字符数估。"
2. **语言差异是 1.x 倍，缓存是 50 倍**：同一模型下（非高峰）中文/英文差 1.6 倍，
   而缓存命中/未命中差 50 倍（0.003 vs 0.15）。**先修前缀稳定性，再抠措辞。**
3. **高峰溢价 2 倍**：北京时间工作日 09:00-12:00、14:00-18:00 正好是上班时间。
   批量实验/回归跑批放到晚上或周末，成本直接打对折——这比换模型安全得多。

# 补齐（2026-10-30）

## 补齐 1 · 三种架构，先分清你手上的是哪种

| 架构 | 代表 | 注意力 | 你会用到 |
|---|---|---|---|
| encoder-only | BERT、embedding 模型（bge/MiniLM） | 双向 | W8 的向量化 |
| **decoder-only** | **GPT / Claude / DeepSeek** | **单向，causal mask** | **你写的一切 agent** |
| encoder-decoder | 2017 原论文、T5 | 编码器双向 + 解码器单向 | 翻译类，基本不碰 |

原论文和 Illustrated Transformer 画的是第三种，3B1B《GPT 是什么》讲的是第二种。所以第一行那句「Transformer 采用 Encoder-Decoder 架构」要加限定语，否则后面 KV cache、mask 全会拧。

→ 工程含义：GPT 没有 encoder。看到「编码器/解码器」的描述时，先确认它讲的是哪一代。

## 补齐 2 · causal mask：生成模型为什么不能看未来

attention 先算一个 n×n 的分数矩阵。训练时整句一次性喂进去并行算 loss；如果不遮住右上三角，位置 3 就能「看到」位置 4 的答案，等于作弊。

```
masked_score[i][j] = (j <= i) ? score[i][j] : -∞
```

softmax 之后，被遮住的位置权重自然变 0。

→ 工程含义：W2 手写 attention 要写两版（不遮 / 遮），对比同一句话的 6×6 权重矩阵，你就明白「为什么生成要一个一个吐」。

## 补齐 3 · 一层 Transformer 到底有什么

```
x → LayerNorm → 多头自注意力 → +x（残差）
  → LayerNorm → FFN（两层线性 + 激活）→ +x（残差）→ 下一层
```

- attention = token 之间**通信**（混合信息）；FFN = 每个位置**独立变换**（提取特征）。
- FFN 通常占参数量 2/3 → 模型的「知识」大量在 FFN 里，attention 负责搬运。
- 残差让梯度直通底层（否则几十层训不动）；LayerNorm 稳住每层输入分布。

→ 工程含义：小模型之所以「知识少但格式还行」，是因为 FFN 小；所以别指望小模型懂业务。

## 补齐 4 · 位置编码：attention 本身不知道顺序

把 token 打乱，attention 的输出只是跟着打乱，**数值关系不变**。所以必须注入位置信息。

现代 decoder 用 **RoPE（旋转位置编码）**：把位置编码成 Q/K 之间的**相对角度**。相对距离天然可算，外推到更长上下文更平滑——这是 1M 上下文能成立的原因之一。

→ 工程含义：长上下文变差，一部分是 RoPE 外推的问题，一部分是 context rot（W4）。

## 补齐 5 · lm_head：从 hidden 到「下一个 token 的概率」

```
hidden (d_model 维) × W_vocab (d_model × V) → logits (V 维)
logits → /T →（可选 logit mask）→ softmax → 概率 → 采样 → 新 token
```

V = 词表大小（DeepSeek 12.8 万，o200k 20 万）。**logit mask 就是在 softmax 之前把非法 token 打成 -∞**。

→ 工程含义：这就是「JSON Schema 约束输出」比「请你输出 JSON」可靠的原因（W4 细讲）。

## 补齐 6 · 一个 token 的完整预测流程（W2/W3/W4 都靠它）

```
文本 → tokenizer → token ids
     → embedding 查表（+ 位置/RoPE）
     → N × [ causal self-attention → FFN ]（残差 + LayerNorm）
     → 最后一层 hidden
     → lm_head → logits（V 维）
     →（logit mask）→ /T → softmax → 采样
     → 新 token → detokenize → 拼回输入，重复
                        ↑
                前文每层 K/V 存进 KV cache，不重算
```

→ 工程含义：**prefill = 一次性算完整段 prompt（并行，吃算力）；decode = 一个 token 一个 token 算（受显存带宽限制）。** 长 prompt 慢在 prefill，长输出慢在 decode。

## 补齐 7 · embedding ≠ 你笔记里的那个 embedding

两个同名不同物的东西：

1. **输入侧的 token embedding**：token id → 查表得 d_model 维向量，和 lm_head 常共享权重。
2. **embedding 模型**（bge / MiniLM）：输入一整段文本，输出**一个**向量表示语义，用**余弦相似度**比远近——RAG 召回用的是这个。

跑一遍 `node ex/embedding-lab.mjs`（中文模型 bge-small-zh-v1.5，512 维），实测：

- 「今天天气不错，适合出去走走」vs「外面的阳光很好，出门散散步吧」：余弦 **0.66**，字面重合 **0**；
- 「我把那个 bug 修了」vs「这个缺陷已经解决了」：余弦 **0.62**，字面重合 **0**；
- 无关句的地板是 **0.32**（不是 0！）；
- 「苹果发布了新款手机」vs「水果店的苹果很甜」：余弦 **0.52**，成了彼此的最近邻——**模型翻车**。

→ 工程含义：① 阈值不能照抄网上的 0.8，要按自己的数据标；② 单靠向量会栽在词义消歧上，生产要 BM25 + 向量混合 + rerank；③ 换模型 = 换向量空间 = 重建索引。
